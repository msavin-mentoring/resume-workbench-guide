# Покрытие вакансий — [ученик / целевая роль]

Сырой список в `references/vacancy-requirements-raw.md` даёт лексику спроса, но не число независимых вакансий. Для PHP backend есть датированный [локальный банк](../references/vacancy-bank-2026-09-29.md) с ID задач (`T`), обязательных требований (`R`), плюсов (`P`) и контекста стека (`S`). Это обзор спроса, не перечень вакансий для отклика: не исключать карточки из обзора из-за уровня, географии, формата, статуса или несовпадения стека. Разделять сегменты и считать разные карточки, а не повторения слов; для других ролей без датированного набора указывать частоту `н/д`.

## Корпус и сегменты

- Смежные сегменты: [CMS/e-commerce, fullstack, руководство и др.; число карточек и глубина чтения отдельно]

## Матрица требований

Покрытие текста резюме: `explicit`, `semantic`, `missing`, `conflicting`. Отдельно указывать статус доказательства кандидата: прямое подтверждение, реконструкция, вопрос или портфолио-план. Решение: `оставить`, `усилить`, `обсудить`, `не включать`. Частоты задач/обязательных требований (`T/R`) не смешивать с плюсами/стеком (`P/S`); для каждой группы показывать знаменатель своего сегмента.
