## Повторяющиеся поисковые намерения

Это **нормализация**, а не дословные цитаты и не частотный рейтинг. Для каждого намерения проверять наличие подтверждённого эпизода в claim ledger и отмечать конкретные вакансии в coverage.

| Намерение | Узнаваемые слова/словосочетания для естественного употребления | Куда обычно относится |
|---|---|---|
| Производительность данных | оптимизация SQL-запросов, индексы, план выполнения, EXPLAIN ANALYZE, сложные запросы, транзакции | Достижение, если есть конкретный запрос, проблема и эффект; иначе типовые задачи |
| Надёжность асинхронной обработки | фоновые задачи, очереди, retry, DLQ, идемпотентность, дедупликация, повторная обработка | Достижение при понятном failure mode и результате |
| Внешние системы | REST API, интеграция с внешними сервисами, webhooks, rate limits, пагинация, версии контрактов | Достижение при решённой проблеме надёжности/масштаба; обычное API — задача |
| Архитектура | проектирование серверной части, модульный монолит, межсервисное взаимодействие, микросервисы, рефакторинг legacy | Называть конкретную границу и зачем меняли; не объявлять микросервисы без факта |
| Production ownership | инциденты в продакшене, логи, метрики, трассировки, сопровождение релизов, откат | Достижение при снижении частоты/времени восстановления; иначе ответственность |
| Качество и поставка | unit/integration tests, code review, технический долг, CI/CD, воспроизводимость сборок | Чаще типовые задачи; достижение — когда есть улучшение процесса/качества |

Полные тексты карточек здесь намеренно не дублируются: ссылки ведут к оригиналам, а короткие фрагменты достаточно точно фиксируют лексику для последующего покрытия вакансий. Если источник исчезнет, потребуется отдельный разрешённый способ архивирования; эта таблица не заменяет оригинальное описание.
